# GPU hard admission: bounded staged design — 2026-09-06

Read-only source audit during release 42922. No source changes, tests, builds, device runs, installations or new operators. Starting evidence: `docs/gpu-resource-contract-investigation-2026-09-06.md`. Source locations below refer to this checkout; the locked driver wrapper is cudarc 0.19.9 (`Cargo.lock:1289`).

## Contract and minimum valid scope

The minimum device repair must make `QE_GPU_CACHE_MB` a hard ceiling on **requested bytes of all engine-owned device allocations**, resident AND transient AND awaiting retirement. It cannot honestly mean total VRAM: CUDA context/module/event overhead, driver allocation granularity and CUDA allocator pool retention are outside these requested layouts. Report that distinction, including device allocator/memory telemetry if available. CPU cgroups do not bound VRAM. Do not introduce an unlimited mode or silently grow a budget to fit a request.

A cache-only refusal in `reserve` is insufficient because run scratch bypasses it. The minimum acceptable tranche is fallible checked admission for every device allocation below, ownership through actual retirement, and recorded correct fallback on denial. Preserve at least one fitting real device workload. Independently bound job metadata admission in the same tranche; do not claim full host-memory safety until provider/staging work is covered in the later stage.

Let C=number of required numeric columns, P=predicate count, S=expanded slots including presence, G=group count. The current kernel requests device scratch:

`8*C + 16*P + 20*S + 8*512*G*S` bytes.

The terms are pointer table, predicate column/op/value arrays, kind/input/c0/c1/c2 arrays, and partial output. All multiplications/additions must be checked, not merely bounded after overflow. Validate G*S<=96, indices/counts fit CUDA i32/i64, required columns are present and equal-length, codes have matching length, and field/aggregate counts are consistent before borrowing pointers or allocating. Current `n=min(column lengths)` is not a substitute for equality. Bare COUNT(*) is already declined (`plan_gpu_agg:396`); retain that scope.

## Stage 1: worker-owned admission and correct retirement

Introduce a small pure checked ledger and typed `GpuAdmissionError`/fallback reason. Keep its authority entirely on the existing single GPU worker. Track resident, active transient and retiring requested bytes separately, plus total/high-water and refusal counts. An owned device buffer couples its CudaSlice with a byte token; use explicit retirement rather than assuming field Drop immediately frees VRAM. Cache insertion consumes an upload token; allocation failure retires partial buffers and releases only after confirmed retirement. Existing entry replacement must first retire the old entry, or reject duplicates; never increment totals blindly when HashMap::insert overwrites.

`admit(need, protected_keys)` checks individual oversize before destructive eviction, evicts only eligible LRU entries, and returns a reservation only if checked total+need<=limit. Run preparation validates the entire working set and calculates scratch before extracting raw pointers. Protect all needed columns/codes during scratch admission; if their bytes plus scratch cannot fit, return recorded CPU fallback without evicting a run input. Because the worker is serial, scoped protection is sufficient; no new concurrent kernel scheduler is required. Readiness on the caller remains only a hint: queued uploads can evict columns before Run reaches the worker.

Capture a checked configured limit per worker operation. Preserve current reconfiguration only at serialized job boundaries: on a lower limit, retire/evict enough entries before starting more work, and record old/current limits and retirement. Reject byte-conversion overflow instead of saturating `mb*MiB` into a near-unlimited value. Unsupported or zero inputs should have an explicit documented parser policy; do not let a supplied enormous number silently evade the budget.

**Driver lifetime proof required:** cudarc `driver/safe/core.rs:800–819` drops CudaSlice by `free_async` when supported; otherwise synchronizes/free_sync. `alloc:1534–1560` calls malloc_async/sync; `memcpy_stod:1586` allocates then copies; `alloc_zeros:1563` allocates then memset. Rust object destruction therefore does not establish completed device retirement. Simplest auditable first implementation: explicitly drop retiring slices, synchronize the worker stream, then release their ledger tokens. Likewise keep run transient tokens until all run buffers are dropped and synchronization succeeds. This introduces measurable synchronization cost; record it rather than prematurely optimizing away the fence. An event-based retiring list is a later equivalent improvement after tests. Do not early-release on CUDA error: if completion/free cannot be established, mark the worker unavailable and retain/quarantine unresolved accounting through context teardown.

Cudarc allocation itself also creates tracking events after allocating raw storage (`core.rs:1546–1555` uses `?` before CudaSlice construction). This requires an upstream-wrapper failure-path audit: a partial event-creation failure may return no CudaSlice to retire. Treat unexplained driver allocation failure as unresolved device ownership, not proof zero bytes remain. A safe minimum can disable further device admission after such a failure, preserve its charge, and use CPU fallback; a dependency fix is a separate reviewed change, not assumed here. No new unsafe allocator wrapper is proposed.

## Stage 2: bounded requests and cancellation/fallback semantics

Replace unbounded mpsc with bounded synchronous `try_send` (never blocking runtime threads). Reserve owned request metadata before cloning long column/spec strings; a count bound alone does not bound bytes. Upload jobs retain provider identity/Arc but not preloaded payload; the Arc may retain large pre-existing provider state, so explicitly distinguish fixture/provider residency from copied queue metadata. Exact externally retained provider ownership remains a broader contract.

Use a submission guard that removes the corresponding dedup key on full/disconnected queue, error, panic or cancellation. Avoid guard Drop locking `queued` while `request` still holds that mutex: perform insertion/submission/rollback with defined lock scopes. Upload/BuildCodes failures must not poison unrelated columns. Commit `rows[pid]` and resident metadata only with an accepted cache entry, or remove orphan row metadata after unsuccessful attempts. Keep eviction and re-upload keyed to existing immutable snapshot identity; an outdated snapshot must never fulfill a new identity.

A Run job checks `reply.is_closed()` before layout/allocation and before kernel launch. Cancellation after launch does not interrupt CUDA; finish/retire safely, discard the result, release its host reservation, and record cancellation separately. Existing detached worker should have an explicit terminal health state: worker panic/death clears eligibility and fails pending replies; stale `ready`/queued state must not live forever in the process OnceLock. Do not catch an arbitrary provider panic and keep using potentially compromised GPU state without a defined reset; transition unavailable is a conservative fallback.

Use structured reason counters: cache-miss/cold, queue admission, device admission, unsupported domain, upload/provider failure, missing residency at execution, CUDA failure, cancellation. Preserve a successful-run/device counter only after launch and successful completed result; cache upload alone is not acceleration. GPU fallback must execute the original CPU operator once with its normal budget, not present a resource refusal as a successful GPU result.

`GpuAggExec` currently delegates `output_partitions` to inner but, after deciding GPU, answers only on partition0 and returns empty for all others. Runtime failure only calls `inner.execute(0)`. For a multi-partition inner, that can omit CPU outputs. Current common aggregate delegates are single-output, but the public wrapper contract is not restricted. Minimum safe scope: only choose GPU when inner declares exactly one partition; otherwise consistently use CPU for all partitions, and call `check_partition`. A broader shared asynchronous outcome/replay mechanism is unnecessary for the minimum fix. Test zero/multiple declared partitions explicitly. Do not infer single partition from a costing hint.

## Stage 3: host allocations (necessary for full resource certification)

Pass real query/context pool ownership to GPU work; device cache is process-resident and needs its own explicit bounded ledger, while per-query host staging must compose with the existing ancestor pools. Background cache fill may outlive its request, so assign a bounded context cache-fill pool with retained owner/cancellation policy instead of borrowing a dead query's budget or spawning an independent unlimited root.

For numeric upload: reserve checked exact converted length before Vec allocation, use `try_reserve_exact`, account actual capacity before retaining growth, convert directly (avoid temporary Int32 cast arrays). For codes: charge code Vec growth, map/table capacity, temporary key strings and retained labels before allocation. Avoid duplicate key allocation per input row when an existing key can be borrowed, but do not label this optimization a budget proof. Validate logical NULLs after dictionary decode and safely reject unsupported types/casts; existing unwraps and unchecked `i64::abs` on MIN are separate concrete panic routes, and group NULLs currently read via `value(row)` rather than validity checks. They need correctness regressions or explicit unsupported fallback before claiming broad supported-input coverage.

The blocking `TableProvider::scan` returns an already-collected Vec. Admission *after* that call cannot protect provider materialization. A complete host fix needs an audited streaming/provided-resident scan contract or pre-admitted actual bound; absent one, decline asynchronous GPU population before scan for that provider. Do not use estimated rows/width as proof. This restriction must be paired with a supported bounded/resident provider path so a fitting real device regression still runs.

Readback must avoid `memcpy_dtov`'s infallible Vec allocation (`cudarc core.rs:1621`): reserve first, construct a fallible initialized host Vec and use existing `memcpy_dtoh`; account merged/present/output arrays independently. The <=96-bin kernel bound limits partial length but does not itself reserve host bytes or bound label widths. Driver staging/pinned memory and CUDA runtime overhead remain separate measured qualifications.

## Acceptance sequence and tests

1. Pure ledger/layout tests without CUDA: every size overflow, just-fit/one-byte-over, single oversized column, protected working set+scratch denial, failed allocation rollback, replacement, eviction/re-upload, lower-budget transition, and retiring bytes not reusable before explicit completion. A fake allocator counter must prove denial happens before an allocation call. Verify the scratch formula against each upload's typed element count.
2. Deterministic lifecycle tests using job/allocator seams: full queue rolls back dedup, worker disconnected/panic releases request owners and marks unavailable, cancelled queued Run makes zero allocations/launches, cancelled running Run holds tokens until completion acknowledgement, failure at each of the ten run allocations cleans earlier buffers, failed retirement quarantines bytes. No sleeps as assertions.
3. CPU fallback SQL/oracle tests: insufficient device or queue capacity gives the exact supported count/integer result and independently tolerated floating result; all declared CPU partitions consumed, invalid partition rejected, NULL/dictionary-NULL and i64::MIN reject safely, no global poison/retry lockout.
4. Real GPU fitting gate in a dedicated process, contained and sequentially coordinated: use existing `.scratch/public-bench/custom-gpu-float-smoke/dataset.json` (600,000 float rows, unchanged historical Q1/Q6), fresh same-binary CPU control and GPU samples. Start with256MiB (existing fitting target), require actual completed device-counter increments and exact/tolerant typed oracle, plus ledgerpeak<=recorded limit. Record resident/transient/retiring peaks, queue/staging peaks, all fallbacks and driver/device memory separately. This is custom supported-domain validation, not canonical decimal acceleration.
5. Real boundary cases under deliberately smaller injected budgets: individual column too large, columns fit but scratch does not, group codes plus resident columns, eviction then re-upload, mutation identity, failed upload and cancellation. At least one small exact COUNT(col)/bounded-integer SUM fixture must execute on device rather than globally falling back. Device unavailable is an explicit skip/blocker; old tests' print-and-return must not be counted as hardware certification.
6. Only after correctness/resource gates: repeat same-binary warm/cold upload and latency measurements. Preserve original SQL/provenance and classify universal fallback as insufficient, even if answers pass.

The first tranche certifies requested device allocation admission and bounded job metadata, not full query/RSS or total-VRAM ownership. Stage3 is required before broader resource-safe GPU claims. None of these future gates is claimed run by this document.
