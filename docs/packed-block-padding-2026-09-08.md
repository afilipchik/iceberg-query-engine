## General cause and fix

`HybridDecoder` incorrectly required final bit-packed padding to be at most seven
values. The local DuckDB writer uses a256-value block and writes the whole block
when finishing a partial block. The final logical values can therefore be followed
by substantially more padding, potentially containing old buffer contents.
The encoding run length describes packed storage; it is not the page's logical
value count. See DuckDB checkout1c27c54f27bea397d18d86f7c0d6a9f1d4aa85f8,
`extension/parquet/include/parquet_rle_bp_encoder.hpp`, `WriteCurrentBlockBP`.

The Parquet grammar represents packed runs in groups of eight and bounds run
lengths to a signed32-bit range. It does not establish our former universal
seven-value padding check. [Parquet encoding specification](https://github.com/apache/parquet-format/blob/master/Encodings.md#run-length-encoding--bit-packing-hybrid-rle--3).

The decoder now emits only the caller-supplied logical page count and ignores the
unused suffix of a final packed block. It still checks encoded byte extents,
requires all actual value bits, rejects bytes outside the declared run at stream
completion, enforces the format run-length bound and validates the domain of each
logical value. Repeated-run overshoot is still rejected. This is independent of
SQL text, table identity, scale factor or a particular dictionary's cardinality.
Output admission, poisoned-error behavior and retryable memory denial are unchanged.
