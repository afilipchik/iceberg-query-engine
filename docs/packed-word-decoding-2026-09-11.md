Our current candidate still calls `value()` and stages cursor/domain checks per dictionary ID through `try_extend_reserved`. Removing the bit-at-a-time loop is therefore one bounded improvement, not parity with a batch decoder. If measurements justify further decoder work, the next shared boundary is run-aware output spans: validate the run and available output reservation, decode a bounded span, validate every logical dictionary ID, then publish cursor/output together. Preserve trimmed tails and padding rules; reject a late invalid ID without publishing a prefix. A repeated dictionary-ID span can validate its value once, while packed spans need full domain checks. Keep refusal-before-consumption and terminal malformed-stream behavior. No bulk implementation, attribution of CPU percentage or additional speedup is claimed.
