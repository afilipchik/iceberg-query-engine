# Variable-output integration review

Source-only review, 2026-09-06; source593 frozen. No source/test changes or runtime work. The prefix helper is a sizing primitive, not a complete allocation boundary. Its narrow compact non-null-index Arrow-take proof remains sound for supported ordinary byte arrays; it cannot certify a zero-copy sliced tail, retained dictionaries, decoder work, or arbitrary join output.

## Smallest complete milestone and blocker

The smallest coherent milestone owning **decoder + decoded tail + emitted output** is a raw, primitive/ordinary-byte, non-nested scanner with an admitted allocation domain throughout Parquet decoding and compact output construction. It is not achievable by adding `select_prefix` after `reader.next()`. Current Parquet58.4 byte decoding uses infallible capacity growth before that callback: `parquet/src/arrow/array_reader/byte_array.rs:374–386` reserves offsets and estimated value bytes; `:492–493` reserves actual total decoded bytes, with more encoding-specific reserves at :551/:592. Page reads, decompression, dictionary pages, offsets/validity and predicate decoding also allocate upstream. A decoded output's logical byte count neither bounds decompression memory nor repeated dictionary-value expansion.

Consequently there is a concrete prerequisite, not a claim that a local helper closes this scope: inventory and replace/interpose the allocating decoder/page-reader paths with a fallible budget-aware allocator/owner API, or introduce a separately audited bounded decoder for an explicitly supported physical encoding subset. Current public reader builder supplies row count/projection, not the required allocator contract. Merely reserving footer uncompressed bytes, largest observed value or `rows*average_width` is not a proof. A local fork/dependency change would require separate review; none is implemented here. Malicious/inconsistent metadata must fail before allocation even in the supported subset. No IPC detour or eager full-file conversion is a safe substitute.

A smaller **output-only** milestone can be useful experimentally but must be named that way and must not satisfy this decoder/tail requirement. It would own compact copies after receiving an already resident input from a separately owned provider. This matches the existing resident-input boundary; it does not certify raw scan decoding.

## Concrete scanner integration points

- `streaming_parquet_scan.rs:355–402` constructs the per-partition unfold state. Replace the raw reader slot with an owner containing decoder reservations, decoded batch/tail, offset cursor and admitted output buffers. Preserve work-item ownership and declared partition counts. Do not create a hidden all-partition collector.
- `:425–446` calls synchronous `reader.next()`, then projection reorder and `wrap_batch`. Admission has to precede reader growth, not appear only here. An owned decoded batch may remain across multiple prefixes, but its guard must cover its actual retained backing allocations until the final tail disappears. A slice's visible bytes do not justify releasing its original owner. Do not wait for more budget while retaining an unreserved remainder.
- `:581–659` creates static and runtime predicate readers. Filter-only columns must be inside the decoder domain even when omitted from final output. Preserve existing runtime-filter refresh at each row-group open, sequential AND semantics, SQL NULL behavior, root projection mapping, aliases and duplicate output columns. Predicate kernels/casts can allocate or fail; narrowing the first supported slice must be explicit, not silently removing predicates.
- `:696–703` maps fixed output normalization. Variable output needs a stateful prefix emitter before this final map, with compact output construction that strips hidden NULL payload bytes. `ByteInput::Rows::Range` alone is insufficient: zero-copy slicing retains extra buffers and NULL-hidden values omitted by helper pricing. Use exact validated fixed/byte buffer builders with fallible preallocation, checked offset domain and admitted actual capacity excess. Array/schema/header/index metadata and simultaneous original+compact+queued copies all need named owners.
- `:408` IPC iteration and `read_row_group` near :832 remain separate paths. First raw-only capability must explicitly decline IPC sidecars and preserve current routing/fallback. Do not infer allocation provenance from Buffer capacity/custom ownership.

Suggested ownership decomposition: a retained decoder domain for page/dictionary/state; a retained decoded-batch domain; a compact output allocation domain; and a queue-copy envelope. These are shared children of the existing query pool, not independent roots. Output buffers need an owner-aware stream/batch lease (or backing allocation owner) because RecordBatch alone carries no pool guard. Returning a batch while dropping its reservation is incorrect if downstream still owns its buffers. Preserve leases across wrappers and early consumer drop. Replacing every domain with a fixed envelope is acceptable only after a checked maximum is enforced before every allocation; estimates do not establish that maximum.

Future pulls which request new decoder reservations are **not pool-independent** under the current prepared-queue contract. Either the complete bounded decoder domain is pre-admitted before the output envelope and performs no further same-pool admission, or this scanner must stay Unknown/serial. Do not advertise existing `pool_independent_*` merely because emitted compact bytes are bounded. Byte budget comes from a checked shared allocation policy including concurrency, not an arbitrary fixed string maximum. Named refusal for an indivisible value preserves SQL; truncation, omission and silent encoding fallback do not.

## Why scanner output alone cannot restore every nested pipeline

`HashJoinExec::prepare_queue_input` near :1800/:1837 requires per-physical-variant gather metadata to establish joined copied bytes. A scan output quantum B only gives worst-case per-element B, so repeating one value 4096 times can require ~4096B. It cannot be substituted for useful actual maximum-value metadata without pessimistic admission. The systemic extension is independently byte-bounded join emission, not removing the prepared proof.

`InnerProbeStream::next_batch` :2256 retains a probe batch, evaluated keys, hashes and cursor. :2319 onward allocates at most4096 candidate entries; this bounds rows, not strings. :2390 gathers filter intermediates before final :2411 `create_joined_batch`. Integrate actual prefix pricing **before each allocation**, retaining bounded pending candidate indices and exact cursor position for the un-emitted suffix. Duplicate indices must emit repeatedly. The probe/source owner must survive all suffixes. Yield by examined-candidate work even when NULL/filter rejects all rows; cancellation must drop all leases.

For the first join slice, use unfiltered Inner, single actual columnar build batch, ordinary fixed/byte outputs, no dictionary-encoding alternative, no multibatch concat, and already owned probe/build buffers. Preserve existing other paths as explicit unsupported ownership scope. `create_joined_batch` :4800 onward may synthesize Dictionary(Int32,Utf8) for small build strings; this encoding retains a complete dictionary child and invalidates a plain-byte prefix estimate. Either implement separate exact dictionary charge/remapping or select a documented general plain compact gather for this capability. An environment flag must not silently change the declared bound. Residual filtering needs its own intermediate byte-bound stage before it can join the certified slice. Row-store fixed gathers have their separate proof and are not the variable-width blocker.

Recursive prepared output metadata may expose a runtime-enforced Bytes bound, but Bytes must not be forged into GatherCopyBound. A parent join must use its own byte-bounded gather contract or decline. Some Unknown streams remain owned/reused exactly once; a failed metadata composition must never restart a prepared child.

## Acceptance gates before adoption

1. Allocation-injection tests at page read/decompression/dictionary/offset/value/predicate/compact output stages: named refusal before growth, no allocator panic, all prior owners released; reported excess-capacity growth admitted before next allocation. Include a single huge value and dictionary expansion exceeding a page's raw size.
2. Decoded tail lifetime: an actual multi-prefix file batch with large backing buffer; pool remains charged after first emission, through outstanding output clones and until last source/output owner drops. Consumer cancellation at each stage releases eventual async/blocking owners without deleting live data. No unreserved wait or early guard release.
3. Exact independent values: nullable/sliced strings and binary, hidden NULL payload bytes, empty/all-NULL, i32/i64 offsets, invalid/overflow extents, duplicates, negative decimals/date/fixed values, multiple row groups/partitions, all-filtered early group followed by matching group, reordered/duplicated projections and filter-only columns.
4. Real queue overlap: at least two pre-admitted decoder/output slots can poll concurrently under a private two-worker runtime, root reserved peak never exceeds budget; an unknown provider retains serial semantics. Test failure of slot N releases earlier initialized slots. No source estimate may select this route.
5. Join hot key producing many byte chunks: exact multiplicity, oversized single gathered value refusal, no lost candidate suffix, early-drop work bound, residual-filter explicit decline, dictionary/multibatch scope checks and chained Inner parent behavior.
6. Full existing raw/IPC/provider/public correctness/cap gates unchanged, then matched alternating provider-neutral screens. No performance or ownership acceptance follows from this unrun sizing component.

Recommended next implementation decision: first agree on the decoder allocator/owner API and stream lease transport. Until those prerequisites exist, integrate only against already-owned resident arrays and label raw decoder/tail ownership blocked. This avoids presenting a scanner-only output check as the requested complete resource fix.
