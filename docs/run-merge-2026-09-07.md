# Resumable partial-run merge cursor

`physical/morsel_agg/run_merge.rs` connects completed run reading, transactional
row restoration and exact grouped partial-state merge. It retains at most one
encoded pending frame and one staged partial row, plus admitted reusable scratch.
It is a merge primitive, not the bounded partition scheduler or live fused worker.
The destination and run collection still need a controller-enforced memory policy.

The cursor distinguishes three positions: no frame read yet, verified frame
awaiting restoration, and staged row awaiting destination merge. A decoding
admission denial retains the verified frame and does not call the file reader
again. A destination admission denial retains the staged row. A successful merge
clears staging only after the destination commits. Each successful step therefore
applies exactly one partial row, while false indicates verified EOF. Typed memory
denial is retryable; arithmetic, layout, IO and validation errors poison the
cursor. Dropping the cursor releases its reader, staged owners and scratch.

`FrameScratch` now tracks whether it holds a checksum-verified payload. Reading
invalidates the previous view, and the accessor refuses unverified scratch. The
merge cursor marks a frame pending only after `RunReader` also accepts its run
count/EOF boundary. After restoration it invalidates the frame view and owns the
staged values. Buffers retain admitted capacities for reuse; holding one frame
is not a fixed byte limit independent of row width.

Final gates pass **81 morsel plus16 ownership tests**, zero failures/ignores;
three new tests use actual spill files. Repeated denial after reading a frame
leaves the destination empty until retry succeeds; two copies of a four-row
partial produce COUNT8, AVG25 and exact decimal coefficient8a. Repeated denial
with a staged row preserves it and commits COUNT1 exactly once after pressure
is released. The file remains alive after its run capability is dropped because
the cursor owns a reader. COUNT overflow into an i64::MAX destination remains
terminal and leaves that destination unchanged. All files and reservations clean
up after owners drop. The earlier80-test run is not additional final coverage.
