📖 Overview: The Big Picture

What Are We Building?

A high-performance SQL query engine in Rust that processes columnar data (Apache Arrow) and targets TPC-H benchmark performance comparable to DuckDB.

🎓 Key Insight: We're currently 136x slower than DuckDB overall, but this is dominated by a single query (Q21 at 2790x). Fix Q21, and we drop to 11x slower. That's the power of understanding your bottleneck.

🐛 Layer 0: Bugs & Foundation

⚠️ Critical Rule: Fix bugs BEFORE optimizations. Optimizing buggy code doesn't make bugs faster—it makes them harder to find and more damaging when they hit.
ID Issue Impact Blocks Fix
B1 Lock .unwrap() panics Runtime crashes All parallel work Replace with expect()
🎓 Why This Matters:
When a thread panics while holding a lock, the lock becomes "poisoned." Any subsequent .lock().unwrap() will panic, cascading the failure. In parallel code, this can bring down the entire query.

Locations: morsel.rs:176, vectorized_agg.rs:242, delim_join.rs:45-56
B2 Spilling disabled Can't handle >memory SF10+ benchmarks Debug and re-enable
🎓 Spilling Explained:
When data exceeds memory, operators must "spill" to disk and merge later. This is disabled in memory.rs:222 with comment "until bugs are fixed." Without it, SF10 queries will OOM crash.
B3 Parquet reads ALL columns Wasted I/O Row-group filtering Implement ProjectionMask
🎓 Column Projection:
If a query only needs 3 columns but the table has 50, we're reading 47 unnecessary columns. The TODO is at parquet.rs:104. Parquet supports ProjectionMask to read only needed columns—this is a 10-50% win before any algorithmic changes.
B4 .bak file with Q21 code Confusion, lost work Q21 fix Merge or delete
B5 LIMIT bug (#11) Wrong results Benchmark validity Investigate limit.rs

🎓 Lessons Learned

Lesson 1: Dependencies Matter

Can't safely parallelize with panicking locks. The dependency graph tells you what order to do things.

Lesson 2: Chains Compound

ProjectionMask → Row-group → Joins = multiplicative gains. If each step gives 2x, the chain gives 8x (2³).

Lesson 3: Fix Bottlenecks, Not Everything

Q21 alone is 92% of total time. Fixing it gives 12x overall improvement. This is better than ten 20% improvements.

Lesson 4: Verify Continuously

After each change: run tests, run TPC-H, compare to baseline. Catch regressions early when they're cheap to fix.

The Compound Effect Formula

If improvements are ADDITIVE:
    Total = Sum of individual improvements

If improvements are MULTIPLICATIVE (independent):
    Total = Product of individual improvements

Example:
    P1 (4x) × P2 (2x) × Q1 (10x) = 80x (if independent)
    But P2 depends on P1, so:
    P1 (4x) × P2 (2x) = 8x chain, then Q1 (10x) = 80x total
