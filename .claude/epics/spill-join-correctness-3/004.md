# Task: SEMI/ANTI join spill support — Q4 SF=100 completes cell-exact

## Description

`SpillableHashJoinExec`'s spill path supports only INNER joins; a
SEMI/ANTI build side exceeding the budget refuses by name. Q4 at SF=100
hits exactly this (its `EXISTS` compiles to SEMI). Extend the spill
path to SEMI, and ANTI if the same mechanism covers it safely.

Design (from the epic's Architecture Decision 2 — validate it against
the real code before building):
- Partition routing already co-locates build and probe rows by key
  hash, so existence semantics survive partitioning unchanged.
- The risk is chunked read-back (007's mechanism): for SEMI a probe row
  must be emitted AT MOST ONCE even if its key matches build rows in
  several chunks; for ANTI a probe row may only be emitted after ALL
  chunks have been probed. Mechanism: a per-spilled-partition probe-row
  match bitmap carried across chunks — SEMI emits unmatched-until-now
  matches per chunk (or collects and emits once at end), ANTI emits
  survivors after the final chunk.
- Emission must produce probe-side columns only (existing non-spill
  SEMI/ANTI emission shape) — reuse, don't re-derive.
- Outer joins (Left/Right/Full) STAY refused; update the refusal message
  to name exactly what remains unsupported.

### What shipped (`src/physical/operators/spillable.rs`)

- `finish_via_spill` accepts Inner | Semi | Anti; Left/Right/Full are
  refused with "supports only INNER, SEMI and ANTI joins (LEFT/RIGHT/FULL
  outer joins are not spillable)".
- BOTH orientations (the planner's `build_right_for_left` makes both
  real; Q4 at SF=100 takes build = LEFT = output):
  - probe-side output (swapped): resident partitions decide per probe
    batch (`probe_match_flags` + `take_probe_rows`); spilled partitions
    carry a per-probe-row bitmap across read-back chunks
    (`accumulate_probe_matches`) and emit after the last chunk; ANTI
    emits probe batches whose partition holds no build rows at all
    (previously silently dropped).
  - build-side output (!swapped): per-resident-partition build bitmaps
    (`mark_build_matches`) accumulated across the whole probe stream and
    emitted after it (`take_build_rows`; zero-probe partitions emit all
    rows for ANTI); spilled partitions emit per chunk — exact because
    chunks partition build rows disjointly.
- Two pre-existing spill-path bugs fixed (both reachable by INNER):
  Dictionary join keys were `JoinValue::Null` on the spill path (zero
  matches) — `join_key_arrays` decodes them at the single key-evaluation
  point; an empty partition evicted when the first batch crossed the
  threshold became a file-less `SpilledPartition` (read-back ENOENT with
  sparse keys) — it now stays resident.
