# Task: Extend leaf-resolution/linking for multi-join chaining

## Description

`src/physical/planner.rs`'s runtime-filter wiring (~lines 1517-1590)
resolves a probe-side leaf by unwrapping only `Project` nodes, keyed by
raw leaf pointer in `streaming_scans`. Once a leaf is consumed into one
`HashJoinExec`, a later, independently eligible Inner join touching the
same logical table gets `probe_leaf=SpillableHashJoin`/`Filter` and no
link at all — confirmed live on Q7 (SF=100) and Q9 (SF=10/100) via
`RT_DEBUG=1`. Fix this.

Read `.claude/prds/runtime-filter-chaining.md` and this epic's
`epic.md` in full before starting — the research trail (exact file:line
references, the live `RT_DEBUG` traces) is summarized there; re-read the
actual current code yourself rather than trusting the summary for
anything you're about to change.
