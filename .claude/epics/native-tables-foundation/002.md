# Task: Storage format + manifest — identity, versioning, zone-maps

## Description

Implement task 001's chosen manifest/statistics format and module layout.
This is the core new artifact of the whole epic: a table-owned manifest
(schema, segment/row-group layout, per-segment min/max statistics, a
version/snapshot marker) that replaces the IPC sidecar's current
"shadow a source parquet path's mtime/size" freshness check with real,
independent identity. Segment data itself stays Arrow IPC, mmap
zero-copy, dictionary-coerced for low-cardinality strings — reuse
`ipc_cache.rs`'s existing read mechanism (`Buffer::from_custom_allocation`
over a `memmap2::Mmap`) wholesale; this task does not touch the read path,
only what governs a segment's identity/validity/statistics.

      task 001 specified.
- [x] Table identity is self-contained: a native table's validity/staleness

- [x] Per-segment min/max statistics are recorded for every column type

- [x] Read path unchanged: existing IPC-sidecar mmap/dictionary-coercion

## Technical Details

- **Task 001's decision (full reasoning in `001.md`'s Outcome section):
  a JSON sidecar manifest, NOT an Arrow IPC/Parquet manifest table and
  NOT Iceberg's own Avro format.** New module: `src/storage/
  native_manifest.rs` (sibling to `iceberg.rs`/`parquet.rs`, mirroring
  the existing `lance.rs`/`lance_write.rs` split so this task's file
  stays disjoint from task 003's `native_write.rs` and task 004's
  `native_table.rs`).
- Concrete schema to implement (field names are a starting point, not
  gospel — the shape is what matters): a single `_manifest.json` per
  table directory, via `serde`/`serde_json` (both already dependencies,
  already used for exactly this "table metadata" job in `iceberg.rs`'s
  `TableMetadata`/`Snapshot` structs).
  - `format_version: u32`, `table_id` — a stable identity generated once
    at creation (UUID or content hash), NOT derived from any source
    file's path/mtime/size, per this epic's decoupled-identity
    requirement.
  - `schema`: the Arrow schema (field names/types/nullability). Arrow's
    `DataType` doesn't derive `Serialize` for every variant, so this is
    the one place JSON's simplicity costs a little hand-written mapping
    — resolve the exact representation during implementation.
  - `snapshot: { version: u64, row_count: u64, created_at_ms: i64 }` —
    the version/snapshot marker task 007 hashes for GPU-cache identity;
    task 003 bumps `version` on every full-table replace.
  - `segments: Vec<Segment>`, one per Arrow IPC file: `{ id: u32, path:
    String (relative, e.g. "seg_00000.arrow" — mirrors ipc_cache.rs's
    `rg_NNNNN.arrow` naming), row_count: u64, byte_size: u64,
    column_stats: HashMap<String, ColumnStats> }`, where `ColumnStats`
    mirrors `src/physical/operators/scan.rs`'s existing
    `ColumnStatistics` shape (`min_i64`/`max_i64`/`null_count`/
    `min_f64`/`max_f64`) field-for-field, so task 004's `statistics()`
    and task 005's dense-direct-address consumer need no translation
    layer.
  - A table-level rollup of `column_stats` (min-of-mins, max-of-maxes,
    sum-of-null-counts across segments), computed ONCE when the manifest
    is finalized — a cheap fold over the small in-memory per-segment
    stats task 003 already computes while streaming, NOT a second pass
    over segment data — and stored directly in the manifest so
    `TableProvider::statistics()` (task 004) is an O(1) lookup, matching
    `ParquetTable::statistics()`'s own compute-once-cache (`OnceLock`)
    pattern.
- **Read mechanism, confirmed reusable UNCHANGED, zero refactor needed**:
  `src/storage/ipc_cache.rs::read_row_group(dir: &Path, rg_idx: usize,
  projection: Option<&[usize]>, slice: Option<usize>)` and
  `sidecar_dict_cols(dir: &Path)` are ALREADY `pub fn` and ALREADY
  parameterized purely by directory + segment index — nothing inside
  either function assumes the directory shadows a parquet file. Task
  004's provider can call `ipc_cache::read_row_group(table_dir,
  segment_id, projection, slice)` directly. NOT reusable as-is:
  `sidecar_dir()` (derives a `.qeipc` path from a parquet filename) and
  `is_fresh()`/`stamp_value()` (compare against a source parquet's
  mtime/size) — these are exactly the parquet-shadowing-specific pieces
  this task replaces with the manifest's own `table_id`/
  `snapshot.version`.
- **Write-side dictionary coercion is NOT directly reusable.**
  `ipc_cache.rs::build_sidecar`'s dictionary-candidate detection reads
  PARQUET COLUMN CHUNK METADATA (`col.dictionary_page_offset()`,
  `col.encodings()`) to decide which Utf8 columns are already
  dictionary-encoded in parquet; task 003's write path receives plain
  decoded `RecordBatch`es from arbitrary sources (query result, Iceberg,
  Lance) with no such metadata. Task 003 needs an Arrow-side equivalent
  (cast candidate Utf8 columns to `Dictionary(Int32, Utf8)`, demote back
  to plain if the resulting dictionary is wide — `build_sidecar`'s
  existing "demote wide dictionaries" logic, ~lines 258-315 of
  `ipc_cache.rs`, is the right post-check to mirror even though the
  pre-check differs). Flagged here because it touches this task's own
  "per-segment statistics... in a shape task 005 can consume" criterion:
  dictionary coercion changes a column's Arrow type, which the
  manifest's declared schema must track consistently with the segment
  files' actual IPC schema.
- Precedent for the self-describing-versioned-layout STRUCTURE (not the
  wire format — task 001 explicitly did not adopt Avro):
  `src/storage/iceberg.rs`'s `Snapshot`/`TableMetadata`/`IcebergTable`
  structs and `open_table`/`is_iceberg_dir` functions. Mirror the
  STRUCTURE (a metadata file naming a version/snapshot plus a list of
  data files with per-file stats), not the Avro serialization.
- Atomic publication: mirror `ipc_cache.rs::build_sidecar`'s existing
  staging-directory-then-atomic-rename pattern (`.<pid>.building` ->
  rename into place) wholesale for the whole table directory (manifest +
  segments together) rather than inventing a new concurrency-safety
  mechanism — this exact pattern is what already makes the sidecar safe
  against concurrent builders/readers across threads AND processes.

### Final manifest schema (precise — tasks 003/004/005/006/007 should not
need to read the source to know what's available)

One `_manifest.json` file per table directory (`MANIFEST_FILE_NAME`),
written via `serde_json::to_string_pretty`, read via `serde_json::
from_str` + semantic validation. `FORMAT_VERSION: u32 = 1` — a manifest
whose `format_version` differs is refused by name, not guessed at.

```
NativeManifest {
    format_version: u32,                          // must equal FORMAT_VERSION
    table_id: String,                              // stable identity (UUID v4), generated
                                                     // once, NOT derived from any source
                                                     // file's path/mtime/size; survives a
                                                     // full-table replace (only `snapshot.
                                                     // version` bumps on replace)
    schema: Vec<ManifestField>,                     // see below
    snapshot: Snapshot {
        version: u64,                               // bumped by whoever performs a
                                                     // full-table replace (task 003)
        row_count: u64,                              // == sum of segments[].row_count
                                                     // (validated)
        created_at_ms: i64,
    },
    segments: Vec<Segment> {
        id: u32,                                    // ALSO the index ipc_cache::
                                                     // read_row_group/sidecar_dict_cols use
        path: String,                                // MUST equal
                                                     // Segment::expected_file_name(id) ==
                                                     // format!("rg_{id:05}.arrow") -- see
                                                     // "Load-bearing finding" below.
                                                     // Validated; a mismatch is a hard Err.
        row_count: u64,
        byte_size: u64,
        column_stats: BTreeMap<String, ColumnStats>, // keyed lowercase, unqualified column
                                                     // name -- same convention
                                                     // TableStatistics::column_stats and
                                                     // disjoint_group_hint already use
    },
    table_stats: BTreeMap<String, ColumnStats>,     // table-level rollup (min-of-mins,
                                                     // max-of-maxes, sum-of-null-counts across
                                                     // segments), computed ONCE by
                                                     // NativeManifest::build/rollup -- an O(1)
                                                     // lookup for TableProvider::statistics()
}

ColumnStats {                                       // field-for-field mirror of
                                                     // src/physical/operators/scan.rs's
                                                     // ColumnStatistics (minus ndv_est/ndv_str,
                                                     // which are DERIVED at the point of
                                                     // building TableStatistics, not stored
                                                     // here)
    min_i64: Option<i64>,                            // int8-64, uint8-32, date32, date64
    max_i64: Option<i64>,                            // (NOT uint64 -- would silently wrap;
                                                     // matches lance.rs's own exclusion)
    null_count: Option<u64>,                         // EVERY column type, always populated
                                                     // (cheap, type-agnostic; see the Lance
                                                     // float-pre-aggregation lesson in
                                                     // CLAUDE.md for why this must not be
                                                     // int-only)
    min_f64: Option<f64>,                            // float32, float64
    max_f64: Option<f64>,
}

ManifestField { name: String, data_type: ManifestDataType, nullable: bool }

ManifestDataType =                                  // curated Arrow DataType subset;
    Null | Boolean                                  // unsupported (List/Struct/Map/
  | Int8 | Int16 | Int32 | Int64                     // FixedSizeList/...) is refused BY NAME
  | UInt8 | UInt16 | UInt32 | UInt64                 // (QueryError::NotImplemented naming the
  | Float32 | Float64                                // type), never silently dropped/guessed
  | Utf8 | LargeUtf8 | Binary | LargeBinary
  | Date32 | Date64
  | Timestamp { unit: Second|Millisecond|Microsecond|Nanosecond, tz: Option<String> }
  | Decimal128 { precision: u8, scale: i8 }
  | Dictionary { key: Box<ManifestDataType>, value: Box<ManifestDataType> }  // recursive;
                                                     // covers ipc_cache.rs v2's own
                                                     // Dictionary(Int32, Utf8) coercion
```

One deliberate refinement over the task's starting-point spec text:
`column_stats`/`table_stats` use `BTreeMap<String, ColumnStats>` where
the spec text said `HashMap` — for deterministic, sorted, diffable/
greppable JSON (matching this format's own "human-readable" design
goal). Converting to `HashMap` (task 004's `TableStatistics::
column_stats`) is exactly as trivial as `HashMap` -> `HashMap` would
have been (`.into_iter().collect()`), so this costs nothing on the
"no translation layer" requirement.

### Load-bearing finding: segment file names are NOT a free choice

`ipc_cache::read_row_group(dir, rg_idx, projection, slice)` does not
accept a path — it computes one itself via a *private* `rg_path` helper
hard-coded to `rg_{rg_idx:05}.arrow`. For task 004's provider to call
that function (and `sidecar_dict_cols`) UNCHANGED, every segment file
MUST be physically named exactly `rg_{id:05}.arrow` using the segment's
`id` — **not** the `seg_00000.arrow` example name 001.md/002.md's own
planning text used illustratively; that name would silently fail to
read (`NotFound`) via `ipc_cache::read_row_group`. `Segment::
expected_file_name(id: u32) -> String` (= `format!("rg_{id:05}.arrow")`)
is the single source of truth; `segment_full_path(table_dir, id) ->
PathBuf` joins it to a directory. `NativeManifest::validate` rejects any
manifest whose declared `path` disagrees with `expected_file_name`,
turning this mistake into a loud error at write/read time. This required
**zero** changes to `ipc_cache.rs` — confirmed both by static reading
and by two dedicated tests (`read_row_group_reads_a_manifest_described_
segment_unchanged`, `sidecar_dict_cols_reads_a_manifest_described_
dictionary_segment_unchanged`) that write real Arrow IPC files in this
exact layout and read them back through the real, unmodified functions.
**Action for task 003**: write segment N's Arrow IPC file to
`native_manifest::segment_full_path(table_dir, n)`, not any other name.

### Public API surface (`src/storage/native_manifest.rs`)

- Types: `NativeManifest`, `Snapshot`, `Segment`, `ManifestField`,
  `ManifestDataType`, `ManifestTimeUnit`, `ColumnStats`.
- Construction/identity: `NativeManifest::generate_table_id() -> String`
  (UUID v4); `NativeManifest::build(schema: &Schema, table_id: impl
  Into<String>, version: u64, segments: Vec<Segment>, created_at_ms: i64)
  -> Result<Self>` (derives `row_count`/`table_stats` from `segments`,
  validates before returning — the only way to get a `NativeManifest`
  that isn't from `read_manifest`); `NativeManifest::rollup(segments:
  &[Segment]) -> BTreeMap<String, ColumnStats>`; `NativeManifest::
  arrow_schema(&self) -> SchemaRef`; `NativeManifest::validate(&self) ->
  Result<()>`.
- Read/write: `manifest_path(dir) -> PathBuf`; `write_manifest(dir,
  &NativeManifest) -> Result<()>`; `read_manifest(dir) ->
  Result<NativeManifest>` (validates on read too); `is_native_table_dir
  (dir) -> bool`; `existing_table_id(dir) -> Result<Option<String>>`
  (missing dir/manifest -> `Ok(None)`; a manifest that exists but fails
  to parse/validate -> hard `Err`, never silently "absent"); `next_version
  (dir) -> Result<u64>` (1 for fresh, else existing + 1).
- Statistics: `column_stats_for_array(&ArrayRef) -> ColumnStats`;
  `compute_batch_stats(&RecordBatch) -> BTreeMap<String, ColumnStats>`
  (keyed lowercase/unqualified); `ColumnStats::merge(&mut self, &Self)`;
  `merge_stats_into(&mut BTreeMap<..>, &BTreeMap<..>)` — task 003's
  building block for accumulating a segment's stats across multiple
  incoming batches AS THEY STREAM, never a second pass.
- Segment naming: `Segment::expected_file_name(id: u32) -> String`;
  `segment_full_path(table_dir: &Path, id: u32) -> PathBuf`.
- Atomic publish: `staging_dir_for(final_dir: &Path) -> PathBuf` (pid-
  suffixed, mirrors `ipc_cache.rs::build_sidecar`'s `.<pid>.building`
  convention); `publish_table_dir(staging: &Path, final_dir: &Path) ->
  Result<()>` (whole-directory atomic rename; unlike `build_sidecar`, a
  losing rename is a hard `Err` here, not a silent defer — a native
  table IS the table, not an optimization cache over one).
- Schema conversion (used internally by `build`/`arrow_schema`, also
  public for direct use): `schema_to_manifest_fields(&Schema) ->
  Result<Vec<ManifestField>>`; `manifest_fields_to_schema(&[ManifestField])
  -> SchemaRef`.

### Validation semantics (`NativeManifest::validate`, called by both
`build` and `read_manifest`)

Refuses, each with a specific message: an unsupported `format_version`;
an empty `table_id`; an empty or (case-insensitively) duplicate schema
column name; a duplicate segment `id` or `path`; a segment `path` that
disagrees with `Segment::expected_file_name(id)`; a `column_stats` or
`table_stats` entry naming a column not in the schema;
`snapshot.row_count` not equal to the sum of `segments[].row_count`; and
`table_stats` not equal to the fold of `segments[].column_stats` (a
bit-pattern comparison, not derived `PartialEq` — see the NaN note
below). Every failure is a `QueryError::Storage` naming the file and the
specific problem, never a panic and never a silently-guessed value.

**NaN note**: `table_stats`-vs-recomputed-rollup comparison deliberately
uses `f64::to_bits()` equality rather than `PartialEq` (`NaN != NaN`
under `PartialEq` would make validation of a manifest whose data
legitimately contains NaN fail spuriously, even though re-folding the
same stored values twice is fully deterministic). Covered by a dedicated
test.
