# Task: Storage format + manifest — identity, versioning, zone-maps

## Description

Implement task 001's chosen manifest/statistics format and module layout.
This is the core new artifact of the whole epic: a table-owned manifest
(schema, segment/row-group layout, per-segment min/max statistics, a
version/snapshot marker) that replaces the IPC sidecar's current
"shadow a source parquet path's mtime/size" freshness check with real,
independent identity. Segment data itself stays Arrow IPC, mmap
zero-copy, dictionary-coerced for low-cardinality strings — reuse
`ipc_cache.rs`'s existing read mechanism (`Buffer::from_custom_allocation`
over a `memmap2::Mmap`) wholesale; this task does not touch the read path,
only what governs a segment's identity/validity/statistics.

## Acceptance Criteria

- [ ] Manifest format implemented per task 001's decision, in the module
      task 001 specified.
- [ ] Table identity is self-contained: a native table's validity/staleness
      no longer depends on comparing against any external source file's
      mtime/size (unlike today's `ipc_cache.rs::is_fresh()`).
- [ ] Per-segment min/max statistics are recorded for every column type
      that can be usefully zone-mapped (numeric, date — the types
      `try_execute_dense_direct` and general predicate pushdown care
      about), in a shape task 005 can consume directly.
- [ ] A version/snapshot marker exists so a future load (task 003) or
      mutation (out of scope, phase 2) has somewhere to record "this is a
      new complete state."
- [ ] Read path unchanged: existing IPC-sidecar mmap/dictionary-coercion
      code is called, not duplicated. If sharing code with `ipc_cache.rs`
      requires refactoring a function to be source-agnostic, do that
      refactor carefully with the existing sidecar's own tests staying
      green throughout — this is shared, load-bearing code with a
      documented history (three epics of hardening it).
- [ ] Unit tests for the manifest itself: round-trip (write, read back,
      fields match), a corrupted/partial manifest is a clear error not a
      panic or silent wrong answer, statistics are correct for a known
      synthetic dataset.
- [ ] No regression to the existing IPC sidecar cache's own behavior as an
      opportunistic read-through cache for parquet tables — this must be
      purely additive. Full existing suite stays green.
- [ ] `cargo fmt --all -- --check` clean; every build through
      `scripts/claude-safe-build.sh`.

## Technical Details

- **Task 001's decision (full reasoning in `001.md`'s Outcome section):
  a JSON sidecar manifest, NOT an Arrow IPC/Parquet manifest table and
  NOT Iceberg's own Avro format.** New module: `src/storage/
  native_manifest.rs` (sibling to `iceberg.rs`/`parquet.rs`, mirroring
  the existing `lance.rs`/`lance_write.rs` split so this task's file
  stays disjoint from task 003's `native_write.rs` and task 004's
  `native_table.rs`).
- Concrete schema to implement (field names are a starting point, not
  gospel — the shape is what matters): a single `_manifest.json` per
  table directory, via `serde`/`serde_json` (both already dependencies,
  already used for exactly this "table metadata" job in `iceberg.rs`'s
  `TableMetadata`/`Snapshot` structs).
  - `format_version: u32`, `table_id` — a stable identity generated once
    at creation (UUID or content hash), NOT derived from any source
    file's path/mtime/size, per this epic's decoupled-identity
    requirement.
  - `schema`: the Arrow schema (field names/types/nullability). Arrow's
    `DataType` doesn't derive `Serialize` for every variant, so this is
    the one place JSON's simplicity costs a little hand-written mapping
    — resolve the exact representation during implementation.
  - `snapshot: { version: u64, row_count: u64, created_at_ms: i64 }` —
    the version/snapshot marker task 007 hashes for GPU-cache identity;
    task 003 bumps `version` on every full-table replace.
  - `segments: Vec<Segment>`, one per Arrow IPC file: `{ id: u32, path:
    String (relative, e.g. "seg_00000.arrow" — mirrors ipc_cache.rs's
    `rg_NNNNN.arrow` naming), row_count: u64, byte_size: u64,
    column_stats: HashMap<String, ColumnStats> }`, where `ColumnStats`
    mirrors `src/physical/operators/scan.rs`'s existing
    `ColumnStatistics` shape (`min_i64`/`max_i64`/`null_count`/
    `min_f64`/`max_f64`) field-for-field, so task 004's `statistics()`
    and task 005's dense-direct-address consumer need no translation
    layer.
  - A table-level rollup of `column_stats` (min-of-mins, max-of-maxes,
    sum-of-null-counts across segments), computed ONCE when the manifest
    is finalized — a cheap fold over the small in-memory per-segment
    stats task 003 already computes while streaming, NOT a second pass
    over segment data — and stored directly in the manifest so
    `TableProvider::statistics()` (task 004) is an O(1) lookup, matching
    `ParquetTable::statistics()`'s own compute-once-cache (`OnceLock`)
    pattern.
- **Read mechanism, confirmed reusable UNCHANGED, zero refactor needed**:
  `src/storage/ipc_cache.rs::read_row_group(dir: &Path, rg_idx: usize,
  projection: Option<&[usize]>, slice: Option<usize>)` and
  `sidecar_dict_cols(dir: &Path)` are ALREADY `pub fn` and ALREADY
  parameterized purely by directory + segment index — nothing inside
  either function assumes the directory shadows a parquet file. Task
  004's provider can call `ipc_cache::read_row_group(table_dir,
  segment_id, projection, slice)` directly. NOT reusable as-is:
  `sidecar_dir()` (derives a `.qeipc` path from a parquet filename) and
  `is_fresh()`/`stamp_value()` (compare against a source parquet's
  mtime/size) — these are exactly the parquet-shadowing-specific pieces
  this task replaces with the manifest's own `table_id`/
  `snapshot.version`.
- **Write-side dictionary coercion is NOT directly reusable.**
  `ipc_cache.rs::build_sidecar`'s dictionary-candidate detection reads
  PARQUET COLUMN CHUNK METADATA (`col.dictionary_page_offset()`,
  `col.encodings()`) to decide which Utf8 columns are already
  dictionary-encoded in parquet; task 003's write path receives plain
  decoded `RecordBatch`es from arbitrary sources (query result, Iceberg,
  Lance) with no such metadata. Task 003 needs an Arrow-side equivalent
  (cast candidate Utf8 columns to `Dictionary(Int32, Utf8)`, demote back
  to plain if the resulting dictionary is wide — `build_sidecar`'s
  existing "demote wide dictionaries" logic, ~lines 258-315 of
  `ipc_cache.rs`, is the right post-check to mirror even though the
  pre-check differs). Flagged here because it touches this task's own
  "per-segment statistics... in a shape task 005 can consume" criterion:
  dictionary coercion changes a column's Arrow type, which the
  manifest's declared schema must track consistently with the segment
  files' actual IPC schema.
- Precedent for the self-describing-versioned-layout STRUCTURE (not the
  wire format — task 001 explicitly did not adopt Avro):
  `src/storage/iceberg.rs`'s `Snapshot`/`TableMetadata`/`IcebergTable`
  structs and `open_table`/`is_iceberg_dir` functions. Mirror the
  STRUCTURE (a metadata file naming a version/snapshot plus a list of
  data files with per-file stats), not the Avro serialization.
- Atomic publication: mirror `ipc_cache.rs::build_sidecar`'s existing
  staging-directory-then-atomic-rename pattern (`.<pid>.building` ->
  rename into place) wholesale for the whole table directory (manifest +
  segments together) rather than inventing a new concurrency-safety
  mechanism — this exact pattern is what already makes the sidecar safe
  against concurrent builders/readers across threads AND processes.
