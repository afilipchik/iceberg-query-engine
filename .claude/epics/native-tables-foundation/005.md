# Task: Dense-direct-address fast-path compatibility

## Description

`src/physical/operators/morsel_agg.rs::try_execute_dense_direct` — the
engine's fastest aggregation path (the one that gets Q18-class queries to
their documented ~187ms/15M-groups floor) — currently reads key-range
bounds from parquet file footers specifically (opens a
`SerializedFileReader` per file to get them). A native table has no
parquet footer once standalone. Without this task, native tables would
silently never take this fast path even when their data shape qualifies
— a real performance regression relative to querying the same data as
parquet, not just a missed opportunity, and directly counter to this
epic's G4 success criterion.

## Acceptance Criteria

- [ ] `try_execute_dense_direct`'s footer-stats dependency is generalized
      to accept zone-map/statistics data from ANY source that can supply
      it in the right shape — parquet footers (existing, unchanged) and
      task 002's native-table manifest statistics (new) both feed the
      same decision logic.
- [ ] Verify with a real measurement, not assumption: load a Q18-shaped
      dataset (single int/date group key, large group count) into a
      native table via task 003's write path, run the aggregate query,
      and confirm via `QE_AGG_PATH`/`AGG_TIMING` (or whatever diagnostic
      this engine exposes — check current names, may have changed since
      the `duckdb-parity-2` epic) that it takes the dense-direct-address
      path, not a fallback tier.
- [ ] No regression to the existing parquet-sourced fast path — its own
      existing tests and benchmarks stay green/unchanged.
- [ ] If task 002's statistics don't cover everything
      `try_execute_dense_direct` needs (e.g. it needs more than min/max —
      check the actual gate logic in `planner.rs`'s `disjoint_group_hint`
      and related code, recently touched by the `duckdb-parity-2` epic),
      either extend task 002's manifest format (coordinate the change
      back into that task's file/tests if it's already closed) or
      document precisely what's missing and why it's out of scope.
- [ ] `cargo fmt --all -- --check` clean; every build through
      `scripts/claude-safe-build.sh`.
