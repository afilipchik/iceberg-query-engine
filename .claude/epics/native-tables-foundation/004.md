# Task: TableProvider integration — splits, statistics, registration

## Description

Make a native table a real, first-class `TableProvider` the engine can
plan and execute queries against — today's IPC sidecar is a helper called
*from* `ParquetTable`, not a provider in its own right. This task gives
native tables their own provider implementation: `distributed_splits`/
`shard_by_splits` implemented for real (both default `None` today on any
provider that doesn't specifically implement them — meaning a native
table would silently be unshardable without this), `statistics()`
returning task 002's real zone-map data (not `None`), and registration
alongside parquet/Iceberg/Lance wherever tables get registered today
(`ExecutionContext`, `--tables` directory auto-detection, metastore
fileset `format` property).

## Acceptance Criteria

- [ ] `TableProvider` trait implemented for the native table type:
      `scan`, `statistics()` (real min/max/row-count from task 002's
      manifest, not `None`), `distributed_splits`/`shard_by_splits` (real
      implementations — even a simple one, e.g. one split per segment, is
      fine for this epic; sophisticated split-sizing is not required, just
      "not silently absent").
- [ ] Registration: a native table directory is auto-detected the same
      way Iceberg/Lance directories are today (`is_iceberg_dir`-style
      detection in `src/main.rs`'s `--tables` handling), and can be
      registered via `ExecutionContext::register_*` directly.
- [ ] Queries against a registered native table plan and execute
      correctly — join it with a parquet table, aggregate over it,
      filter it — exercising the normal physical planner, not a
      special-cased path.
- [ ] Cell-exact validation: load a native table from an existing source
      (using task 003's write path) and confirm every query type in
      `tests/duckdb_validated.rs`'s pattern returns identical results
      whether run against the source or the native copy.
- [ ] Full suite stays green; distributed M1/M2 gates unaffected (native
      tables don't need to work correctly *inside* a distributed cluster
      yet — this epic's G5 only requires not breaking existing distributed
      behavior for other table types — but `distributed_splits` should be
      real enough that a future distributed epic doesn't start from zero).
- [ ] `CREATE TABLE <name> AS SELECT ...` works end to end through
      `ExecutionContext::sql()` (and therefore the REPL and `/sql` HTTP
      endpoint): parses, binds via the existing `bind_query()`, streams
      into task 003's write path, registers the result so a subsequent
      query in the same session can immediately read it. Per task 001's
      finding (see Technical Details), this is in scope for this epic —
      not deferred to a future one.
- [ ] `cargo fmt --all -- --check` clean; every build through
      `scripts/claude-safe-build.sh`.

## Technical Details

- **Task 001's decisions (full reasoning in `001.md`'s Outcome section):**
  - Module: `src/storage/native_table.rs` — the `TableProvider` impl
    (e.g. a `NativeTable` struct), sibling to `src/storage/
    native_write.rs` (003) and `src/storage/native_manifest.rs` (002).
    Mirrors the existing `lance.rs`/`lance_write.rs` file split so 003
    and 004 never touch the same file (the parallel-safety property the
    epic's own preview note asked 001/002 to guarantee).
  - Read mechanism: call `src/storage/ipc_cache.rs::read_row_group(dir,
    segment_id, projection, slice)` and `sidecar_dict_cols(dir)`
    directly — both are already `pub fn`, already parameterized purely
    by directory + index, with zero dependency on parquet-shadowing. No
    `ipc_cache.rs` refactor needed for the read side.
  - Statistics: populate `TableStatistics`/`ColumnStatistics` (`src/
    physical/operators/scan.rs`) straight from task 002's manifest
    rollup — the manifest's table-level `column_stats` is already
    shaped to match this struct field-for-field (see `002.md`).
  - **SQL DDL: task 001's sizing spike found the lift small (S, ~8-16h)
    and recommends building it in this epic — attached here**, since
    task 003 supplies the raw write entrypoint but registration (making
    the newly-written table immediately queryable) is this task's job,
    and that registration step is the one piece a bare CTAS write
    entrypoint doesn't provide on its own. Concretely, add to this
    task's scope:
    - A new `Statement::CreateTable` match arm in `Binder::bind()`
      (`src/planner/binder.rs` — re-confirmed for task 001 by reading the
      file in full: `Statement::Query` is the ONLY handled variant today,
      every other statement hits the catch-all `NotImplemented`). Bind
      `ct.query` (when `Some`) via the ALREADY-EXISTING
      `self.bind_query()` — confirmed by a `.scratch/` spike that
      `sqlparser` 0.62's `CreateTable.query` field is a `Box<Query>`,
      the IDENTICAL type `bind_query()` already fully handles, including
      joins/aggregates/subqueries/CTEs (spiked with a join+GROUP BY
      CTAS; parsed and bound cleanly). Refuse (by name, not silently)
      `CreateTable` statements where `query.is_none()` (a
      columns-only DDL with no `AS SELECT` — legitimately parses per the
      spike, but is out of scope: this epic is bulk-load/replace only,
      no later `INSERT` to populate an empty table) and refuse the ~25
      other `CreateTable` struct fields this epic doesn't support
      (`or_replace`, `temporary`, `partition_by`, `like`, `clone`, etc.)
      by name, mirroring this binder's existing "match the supported
      shape, `NotImplemented` the rest" convention used throughout
      (e.g. window functions, GROUPING SETS).
    - A new `ExecutionContext` entrypoint for DDL — NOT a reuse of
      `sql()`'s current `&self` signature or its fully-materializing
      execution (see `003.md`'s Technical Details for why: registering
      the new table needs `&mut self`, and a real streaming write needs
      the inner SELECT's `RecordBatchStream` consumed directly rather
      than collected first).
    - Do NOT add `Statement::Insert` handling — this epic is explicitly
      full-table-replace only; `INSERT INTO <existing native table>
      SELECT ...` is phase-2 mutation scope even though `sqlparser`
      parses it equally easily (confirmed in the same spike: `Insert.
      source` is also a `Box<Query>`).
- `src/physical/operators/scan.rs` — the `TableProvider` trait itself and
  `MemoryTable`'s implementation as one reference point (though
  `MemoryTable` is not spill-aware, don't copy that gap — see task 006).
- `src/execution/context.rs` — `register_*` family for the registration
  surface to match.
- `src/main.rs:1238-1243` — the existing `is_iceberg_dir`-style
  auto-detection pattern in `--tables` handling (line numbers verified
  current as of task 001), to mirror for native table directories.
