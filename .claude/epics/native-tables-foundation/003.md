# Task: Write path — bulk-load from parquet/Iceberg/Lance/query results

## Description

The entrypoint that actually moves data into a native table: accept a
stream of `RecordBatch`es (from a query result, a parquet directory, an
Iceberg table, or a Lance dataset the engine can already read) and write
them out as a new native table using task 002's manifest format. Model
this directly on `src/storage/lance_write.rs`'s `write_batches`/
`write_from_parquet` — streaming, no double-materialization of either
side. Full-table replace semantics only (a "load" always produces one
complete new snapshot); no partial append/update in this epic.

## Acceptance Criteria

- [ ] A `write_batches`-equivalent entrypoint accepting any
      `RecordBatch` stream, writing segments + manifest per task 002's
      format, computing per-segment statistics as data streams through
      (not a second pass over written data).
- [ ] A `write_from_parquet`/`write_from_iceberg`/`write_from_lance`-style
      convenience path for each existing source type, matching
      `lance_write.rs`'s streaming-without-double-materializing pattern —
      read the source, write the target, batch by batch.
- [ ] This is also the mechanism a future `CREATE TABLE ... AS SELECT`
      (whether built now per task 001's finding, or as a later fast-follow)
      will call — design the entrypoint's signature so it can take an
      arbitrary query result stream, not just "a whole existing table,"
      even if the SQL surface itself isn't wired yet.
- [ ] Row counts and checksums match the source exactly (mirror
      `scripts/iceberg_gen.py`'s own validation discipline — COUNT(*) +
      SUM() checksums of every numeric column, source vs. written-back
      native table) for every source type tested.
- [ ] Dictionary encoding for low-cardinality string columns applied at
      write time (matching `ipc_cache.rs` v2's existing behavior), not
      left as a follow-up.
- [ ] Full suite stays green; new tests cover at minimum: load from a
      parquet directory, load from an Iceberg table (this session's
      `data/tpch-10gb-iceberg` is available), load from a Lance dataset,
      load from an in-memory `RecordBatch` stream (the CTAS-shaped case).
- [ ] `cargo fmt --all -- --check` clean; every build through
      `scripts/claude-safe-build.sh`.

## Technical Details

- Direct template: `src/storage/lance_write.rs` — its own doc comment
  says outright this is "the path a `CREATE TABLE ... AS SELECT` takes:
  hand it a query result's batches and its schema," and
  `LanceWriteMode::{Create,Append,Overwrite}` is the closest existing
  enum for a mode parameter (this task only needs `Create`/`Overwrite`
  equivalents — no `Append`, that's mutation, out of scope).
- Test data available: `data/tpch-10gb-iceberg` (Iceberg, generated this
  session), `data/tpch-10gb` (parquet), existing Lance datasets under
  `data/`.
