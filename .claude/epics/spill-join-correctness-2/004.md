# Task: Fix the three known sibling bugs

## Description

The prior `spill-join-correctness` epic's task 003 found and characterized
three distinct, real bugs while sweeping for the blast radius of the main
wrong-answer bug — none was fixed (per that epic's own no-guess-fixes
gate, since fixing wasn't its task 003's charter). Full detail:
`.claude/epics/archived/spill-join-correctness/003.md`'s Outcome section.
Fix all three here, each with its own root cause already reasonably
well-characterized (unlike the main bug), each with its own regression
test.

**Re-scope note, added after task 001 (2026-08-27):** task 001 already
fixed the spill-directory collision bug (first bullet below) as a direct
byproduct of its own hash-consistency investigation — it turned out to be
a MORE serious bug than the prior epic's own "fails loudly, never
silently wrong" characterization: under a collision between differently-
sized concurrent queries, task 001 caught it producing a SILENT WRONG
ANSWER (HTTP 200), not just the documented loud crash. Fix: `spill_path`'s
default now embeds `std::process::id()`
(`src/execution/memory.rs`, commits `cd8a33b`/`67f5957` on this branch).
**Do not re-implement this fix** — read task 001's own Outcome section
first. This task's real remaining scope is: (a) verify task 001's fix
is sufficient for the ORIGINAL "fails loudly" symptom too (the HTTP 400/
Parquet-schema-error case), adding a regression test for that specific
symptom if task 001's own tests didn't already cover it, and (b) the
other two bugs below, unaffected by this re-scope.

Independent of task 001's outcome for bugs 2 and 3.

## Acceptance Criteria

- [ ] **Spill-directory collision — VERIFY, don't re-fix.** Confirm task
      001's fix (`src/execution/memory.rs`, PID-embedded default
      `spill_path`) resolves BOTH symptoms: the silent-wrong-answer case
      task 001 itself caught, AND the original "fails loudly" case this
      task was originally written against (two real co-located processes,
      confirm no collision, no `Parquet error: Required field schema is
      missing` / HTTP 400). Add a regression test for whichever symptom
      isn't already covered by task 001's own tests — check first, don't
      assume neither is covered.
- [ ] **`LIMIT` not enforced under spill**: `ORDER BY ... LIMIT` queries
      (Q2/Q3-shaped) under spill pressure return a correct top-K PREFIX
      but don't truncate to N rows. Root-cause and fix, likely in
      `ExternalSortExec`'s spill path or the top-k fusion rule losing
      track of LIMIT under a spilled input (per the prior epic's own
      characterization — verify, don't assume). Regression test: forces
      spill for an `ORDER BY...LIMIT` query, asserts the returned row
      count equals LIMIT, not more.
- [ ] **Sort-spill run-file-not-found crash** (Q10-shaped): `Failed to
      open run file "...sort_0_27/merged_pass0_48.parquet": No such file
      or directory`. Root-cause and fix. Regression test: forces the
      same spill shape, confirms no crash and a cell-exact answer.
- [ ] All three regression tests confirmed to FAIL without their
      respective fix (write them first against unfixed code, per this
      program's own established discipline) and PASS with it.
- [ ] Cell-exact validation for all three, not row-count-only (except
      the LIMIT bug, where the row COUNT itself is the defect — still
      confirm the returned rows' VALUES are correct, matching the prior
      epic's own finding that this bug's symptom is "correct values,
      wrong row count").
- [ ] No regression to the main wrong-answer bug's own characterization
      (these fixes should not change its observed rate — if they
      appear to, report that explicitly rather than silently accepting
      it as a bonus fix).
- [ ] Full suite green; `cargo fmt --all -- --check` clean.
