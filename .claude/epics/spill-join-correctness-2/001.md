# Task: Hash/derived-state-consistency investigation

## Description

The epic's real risk and entry point. A real, merged Trino bug fix
(PR #25892, cited in `.claude/plans/research/2026-08-27-modern-olap-
research-synthesis.md` §2.6) was caused by spilling using one
hash-generator implementation and unspilling using a DIFFERENT one,
silently grouping values incorrectly — same operator class (spilling
hash aggregation/join), same symptom shape (silently wrong, not
crashed) as this engine's own still-open bug. The prior
`spill-join-correctness` epic's own "best remaining hypotheses" list did
NOT include this specific mechanism (it focused on non-idempotent
re-execution, disproven, and a vaguer "mid-computation failure" theory).
This task checks it directly, with instrumentation, not inference.

Read `.claude/epics/archived/spill-join-correctness/` in FULL before
starting — especially `001.md`'s Outcome (the disproven leading
hypothesis, the existing `QE_SPILL_DEBUG` instrumentation, the exact
repro steps and 4.8%/0.34% rate figures) and `003.md`'s Outcome (blast-
radius characterization: not native-table-specific, distributed-
reachable, three sibling bugs). Do not re-derive what's already
established there.

## Acceptance Criteria

- [ ] Identify every derived/cached value computed during
      `SpillableHashJoinExec`'s build/probe path that gets RELIED ON
      AGAIN after a spill/unspill round-trip for the same logical data —
      join-key hash, partition-routing hash, dictionary-encoding state,
      or anything else. Enumerate them explicitly (read
      `build_with_partitioning`/`probe_with_spilling`/
      `process_spilled_partition` in full).
- [ ] For each one identified, instrument (new tracing behind
      `QE_SPILL_DEBUG` or a new task-specific env var, matching this
      file's own existing diagnostic convention) to directly compare the
      value computed in the in-memory path against the value recomputed
      after reading the same data back from a spill file — for the SAME
      rows, across a real repro run.
- [ ] Reuse the prior epic's own repro methodology (`.scratch/
      spill_join_repro/repro.sh` if still present, else re-derive from
      `001.md`'s exact repro steps) — do not redesign the repro from
      scratch.
- [ ] Run enough trials to have real confidence either way — the prior
      epic's own rate estimate (~0.34% pooled) means a handful of trials
      proves little; if task 003 (fault-injection harness) would let you
      run drastically more trials cheaply, consider using it once
      available rather than repeating the prior epic's expensive manual
      loop — check its status/coordinate rather than assuming it must be
      built first.
- [ ] **Confidence gate, explicit, same as the prior epic's own
      precedent**: if this task finds direct evidence of a mismatch,
      design and implement a minimal, targeted fix, with a regression
      test that FAILS without the fix and passes with it — validated
      against the prior epic's own repro AND a broad cell-exact sweep
      (native table AND plain parquet, matching the prior epic's own
      confirmed-not-native-specific finding). If this task does NOT find
      direct evidence after a genuine effort, STOP — do not guess at a
      fix. Report the honest outcome, matching this program's own
      "reliably reproduced, not yet root-caused is a valid outcome"
      culture.
- [ ] If a fix lands: no regression to the O(n²) slowness fix already
      shipped (`spill-join-correctness` task 002) or to any other
      spill-path test.
- [ ] Full suite green (`scripts/claude-safe-build.sh cargo test`, all
      feature combinations); `cargo fmt --all -- --check` clean.
