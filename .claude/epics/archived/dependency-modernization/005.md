# Task: OOM-safe build sandbox

Inserted after the 2026-08-22 incident: a bare `cargo test --release
--features lance` (task 003 verification) peaked at 105G inside the
terminal's cgroup scope and systemd-oomd killed the entire scope —
terminal, Claude session, and remote-control bridge.

Requirement (user directive): under no circumstances may a local build
that Claude runs terminate the terminal. Preferred containerization
(docker) is unavailable without sudo (socket permission denied for this
user), so the fix uses the same cgroup mechanism directly.

## Delivered

- `scripts/claude-safe-build.sh` — wraps any command in a transient
  `systemd-run --user --scope` cgroup under app.slice with hard
  `MemoryMax` (default 64G), `MemorySwapMax=0`,
  `ManagedOOMMemoryPressure=kill`, and `CARGO_BUILD_JOBS=16`.
- CLAUDE.md "Sandboxed Build Rule": all build/test/bench commands must
  go through the wrapper.

## Verification

- Wrapped command lands in `safe-build-*.scope`, not the terminal's
  `vte-spawn-*` scope; `memory.max` reflects the cap.
- Deliberate memory bomb under a 512M cap: killed by the kernel inside
  the scope (exit 137) in seconds; terminal and session unaffected.
- Initial design with a lower `MemoryHigh` band caused reclaim-throttle
  crawl instead of fast failure (swap disabled); default is now
  MemoryHigh = MemoryMax so overruns fail fast.
