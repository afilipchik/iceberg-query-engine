# Task: Distributed parity — Flight on every node of a real cluster

## Description

Make Flight fully functional in the N-process cluster:

- `scripts/cluster_local.sh`: derive per-node flight ports (HTTP port +
  1 convention holds), health-wait includes the flight listener, `stop`
  kills it, `verify` adds a Flight round-trip against each node.
- Membership: `/cluster` JSON (and `DoAction("cluster")`) includes each
  member's flight address so tooling can discover all endpoints from any
  node. Nodes do NOT dial each other's flight ports — internal traffic
  stays on the HTTP transport (design ruling).
- Distributed execution through Flight: a scatter-eligible aggregate
  (e.g. TPC-H Q01) via DoGet on a 3-node cluster reports
  `distributed:true, shards:3` in metadata; a gather-shaped query (e.g.
  Q09 join) also answers correctly; `mode:"off"` in the ticket forces
  local and says so via `skipped_reason`.

## Acceptance Criteria

- [ ] 3-process cluster: same SQL via Flight against node 0, 1, 2 →
      identical results (byte-compared batches)
- [ ] Flight results == HTTP `/sql` results on the same cluster
- [ ] Metadata parity: distributed flag + shard count match the
      x-qe-distributed / x-qe-shards headers for the same statement
- [ ] `cluster_local.sh verify` green including the new Flight checks
- [ ] Suite green; fmt clean

## Technical Details

- `execute_statement` already owns the auto/scatter/gather choice, so
  this task is wiring + verification, not new execution logic. Budget
  the time for harness edges: port collisions, readiness races, and the
  advertised-address derivation (`derive_advertise`) applying to the
  flight port too.
