# Task: Query path — GetFlightInfo, DoGet, tickets, error mapping

## Description

Implement the query lifecycle in `flight.rs`:

- **Ticket format** (serde JSON, versioned):
  `{"v":1,"sql":"...","mode":"auto|force|off"}`. Size-capped at
  `MAX_SQL_BODY_BYTES`. Stateless: any node that can serve `/sql` can
  serve any ticket it minted.
- **GetFlightInfo** (`FlightDescriptor::cmd` = SQL bytes): parse + plan
  via the engine (plan only — do not execute), derive the result schema,
  return `FlightInfo` with that schema, one `FlightEndpoint` (ticket as
  above, `Location` = this node's advertised flight address), and
  `app_metadata` = `{"node_id":N}`.
- **DoGet**: decode ticket → `execute_statement` (task 002's shared
  core) → stream batches with `FlightDataEncoderBuilder` (handles
  dictionaries). Attach result metadata JSON
  (`{"rows":N,"elapsed_ms":X,"distributed":bool,"shards":N?,
  "skipped_reason":...?}`) via `.with_metadata()` on the encoder or the
  final message's `app_metadata` — whichever arrow-flight 53 supports
  cleanly; document the choice in the module docs.
- **GetSchema** for `cmd` descriptors: same plan-only schema derivation.
- **Error mapping** (one helper, used everywhere):
  Parse/Bind/Type → `InvalidArgument`; TableNotFound/ColumnNotFound →
  `NotFound`; not-ready → `Unavailable`; everything else → `Internal`.
  Message = the engine's error Display, never a generic string.

## Acceptance Criteria

- [ ] pyarrow: `get_flight_info(for_command(sql))` → `do_get(ticket)`
      returns correct results for a TPC-H query
- [ ] Result schema in FlightInfo matches the batches streamed by DoGet
- [ ] Empty result sets stream schema-only (0 batches) and succeed
- [ ] Bad SQL → InvalidArgument with the parser message; unknown table →
      NotFound; each observable from pyarrow as FlightError
- [ ] Suite green; fmt clean

## Technical Details

- Plan-only schema: bind the statement to a LogicalPlan and read its
  schema — do NOT execute in GetFlightInfo. If a plan-only path is not
  cleanly reachable, `NotImplemented` GetSchema-for-cmd and put the
  schema only in DoGet's stream (FlightInfo.schema may be empty per the
  Flight spec) — record which way it went.
- Stream from the `query_runtime()` execution without re-buffering: the
  encoder takes a batch stream; feed it the result batches.
- Respect the memory rule: no clone of the full batch vec just for
  encoding.
