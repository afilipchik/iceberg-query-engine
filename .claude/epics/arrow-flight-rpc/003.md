# Task: Flight service skeleton and serve wiring

## Description

Create `src/distributed/flight.rs` implementing arrow-flight's
`FlightService` trait over `Arc<NodeState>`, and start it from `serve`.

Skeleton scope (no query execution yet):
- `Handshake`: trivial success.
- `ListFlights`: one `FlightInfo` per registered table (name as path
  descriptor, schema attached, no endpoints).
- `GetSchema`: descriptor path = table name → that table's Arrow schema
  (via `IpcMessage`); unknown table → `NotFound`.
- `DoAction` with type `"cluster"`: the same membership JSON as
  `GET /cluster`. `ListActions` advertises it.
- All other RPCs: `Status::unimplemented` with the RPC name.

Wiring:
- `ServeOptions::flight_bind: Option<String>` — `None` = derive HTTP
  port + 1; literal `"none"` = disabled.
- `serve`/`spawn` start `tonic::transport::Server` with
  `FlightServiceServer` on a tokio task; `ServerHandle` exposes
  `flight_addr()` and shuts the tonic task down in `shutdown()`.
- `src/main.rs`: `--flight-bind` on the `serve` subcommand, help text
  matching the option's semantics.
- Readiness: Flight starts listening immediately (like HTTP) but
  table-dependent RPCs return `Unavailable` until `state.ready()`.
