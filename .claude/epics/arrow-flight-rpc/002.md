# Task: Extract execute_statement from the HTTP sql handler

## Description

The local-vs-distributed decision and execution live inline in
`server.rs::sql` (~lines 1108–1148). Extract them into a shared function
so the Flight service and the HTTP handler run the IDENTICAL path:

```rust
pub(crate) struct ExecOutcome {
    pub result: QueryResult,            // batches + row_count + metrics
    pub distribution: Option<Distribution>,
    pub fallback_reason: Option<String>,
    pub elapsed_ms: f64,
}

pub(crate) async fn execute_statement(
    state: &Arc<NodeState>,
    statement: &str,
    mode: DistMode,
) -> Result<ExecOutcome, QueryError>
```

It owns: readiness check, queries_total counter, the DistMode::Auto
plan-probe fallback logic, spawning onto `query_runtime()`, and both the
local and `execute_any_distributed` paths. The HTTP handler keeps only:
body/format parsing, `encode()`, and header construction from
`ExecOutcome`.
