# Task: Confirm root cause, fix build-side SEMI/ANTI marking, pin at operator and SQL level

## Description

Write the failing test FIRST: `HashJoinExec` (not the spillable wrapper)
with `build_right=false`, Semi then Anti, Dictionary(Int32,Utf8) keys,
60k build rows over 40 values / 2k probe rows over 20 values, asserted
against a naive count (reuse/port `naive_join_count`). Confirm it fails

fix any sibling. Convert `in_memory_hash_join_findings_from_task004_
fixtures` (spillable.rs tests) into a hard, un-ignored regression test.

(so `l_shipmode`/`o_orderpriority` are Dictionary columns), run a
Semi and an Anti query keyed on the Dictionary column with the build on
the left (shape the planner produces when the left is not >2x the
right), and compare cell-by-cell with the same SQL over the parquet
source.
