# Task: Dictionary keys on the vectorized hash-table path

## Description

`VectorizedHashTable::build` returns "Cannot vectorize key types" for
Dictionary keys, which is why the buggy generic path was reachable at all.
Decode Dictionary key arrays to their value type ONCE per batch at build
time and at every probe entry point (`probe_batch`, `probe_batch_semi`,
and whatever `probe_vectorized`/`probe_one_semi_anti_batch` evaluate),
using the same `compute::cast` the aggregate and the spill path use, so
`can_vectorize_arrays` accepts them. Assert with a test that a
Dictionary-keyed build produces a VHT (not the fallback). Time a
Dictionary-keyed Semi join at SF=10 native before/after (same machine,
back to back) — it must not be slower than the generic path it replaces.

## Acceptance Criteria

- [ ] VHT builds for Dictionary(Int32,Utf8) keys (test asserts the
      table exists / the fallback is not taken)
- [ ] Inner, Semi, Anti, Left over Dictionary keys cell-exact vs naive
      truth through `HashJoinExec` in both orientations
- [ ] Measured: Dictionary-keyed Semi join at SF=10 native, before vs
      after, recorded; not slower
- [ ] Existing hash_join tests + M1/M2 gates green; fmt clean
