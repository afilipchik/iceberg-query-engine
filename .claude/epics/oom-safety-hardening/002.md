# Task: Streaming two-phase reservation for SpillableHashAggregateExec

## Description

`SpillableHashAggregateExec::execute` (`src/physical/operators/
spillable.rs`) still calls `collect_input_partitions_concurrently` —
materialize everything, then decide whether to spill. Replace with the
streaming two-phase reservation `SpillableHashJoinExec::execute_spill_path`
already ships (`compute_build_decision` + `stream_merge_input_partitions`,
`spill-join-correctness-2` task 002): read input batch by batch with a
running size total checked per batch, route to spill partitions the
moment the budget line is crossed. Mirror the join's shape — do not
invent a new pattern.

Builds on the corrected `estimate_batch_size` from the
`spill-size-estimate-fix` epic (external dependency, must be merged
first) so the per-batch running total isn't wrong by ~4,000x for
Dictionary columns.

### Mechanism: the join's streaming two-phase reservation, mirrored

1. **Phase 1** (`execute()`): `collect_input_partitions_concurrently`
   replaced by `stream_merge_input_partitions` (the join's own bounded-
   channel merged stream, reused) + a running `estimate_batch_size`
   total checked per batch against `memory_limit * spill_threshold`.
   Under-threshold completion = the unchanged in-memory delegate;
   crossing = prefix + crossing batch + rest of stream chained into
   `aggregate_with_spilling` mid-stream (`finish_via_spill`'s exact
   shape). `collect_input_partitions_concurrently` remains only for
   `ExternalSortExec` (task 003's scope).
2. **Ingestion**: open-writer spill files (`append_batch_streaming` +
   `close_spill_writers`, 007's plumbing reused byte-for-byte) replace
   the old O(n²) `write_batches_to_parquet` + `merge_parquet_files`
   (deleted); largest-first eviction via `evict_agg_partition_to_disk`;
   new `SpilledAggPartition` tracks per-partition spilled rows + raw
   bytes for the finalize accounting. Batch bytes only are charged here
   (documented divergence from the join: no hash state exists during
   agg ingestion, and finalize state covers spilled rows too, so it is
   priced where it materializes).
3. **Accounted finalize** (007's discipline): per partition, raw bytes
   + `predicted_agg_state_bytes` (worst-case all-unique-groups analogue
   of `predicted_hash_table_bytes`; ~56B bucket + 32B/GroupValue +
   384B/accumulator + 48B/row per DISTINCT) gates read-back BEFORE
   materializing; over-threshold partitions take
   `aggregate_partition_chunked` — streamed parquet read-back re-routed
   with the SAME group hash at modulus `NUM_PARTITIONS * fan` (residues
   of partition idx are exactly {idx + 64j}, so subs are group-disjoint;
   a diverged residue fails loudly). Documented residuals: resident
   batches (~threshold), one sub's real state (~threshold via fan),
   accumulated output, global-DISTINCT value sets.
4. **Dictionary-aware routing** (`partition_batch_by_group_hash`,
   agg-local — the join's `partition_batch_by_hash` untouched per the
   hard boundary): Dictionary group keys decode to values before
   hashing, so Dictionary GROUP BYs actually spread across partitions
   and remain splittable at finalize; routing is stable across the
   Parquet round trip. `batch_with_actual_types` reconciliation
   preserved by construction (all spill writes use actual batch
   schemas; the only declared-schema construction builds from scalars).
