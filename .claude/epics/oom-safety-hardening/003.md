(`src/physical/operators/spillable.rs`): replace
`collect_input_partitions_concurrently` with batch-by-batch ingestion

budget, instead of materializing all input before the spill decision.

### Mechanism: 002's streaming two-phase reservation, mirrored — plus streamed merge delivery

1. **Phase 1** (`execute()`): `collect_input_partitions_concurrently`
   replaced by `stream_merge_input_partitions` (the shared bounded-
   channel merged stream) + a running `estimate_batch_size` total
   checked per batch against `memory_limit * spill_threshold`.
   Under-threshold completion = the unchanged in-memory
   `MemoryTableExec` + `SortExec[::with_fetch]` delegate; crossing =
   prefix + crossing batch + rest of stream chained into the EXISTING
   `generate_runs` (already batch-by-batch: buffer to ~threshold, cut a
   sorted run via `flush_run`, repeat) — exactly the task's "change WHEN
   input becomes runs" shape. `QE_SPILL_DEBUG` traces the crossing and
   run count.
2. **Streamed merge delivery** (forced by the scenario's arithmetic:
   ingestion alone cannot flip it — the merge previously materialized
   each multi-pass chunk's ~1.6GB output AND the entire 4GB final
   result in Vecs). The k-way merge core became sink-based
   (`SortRunMerger::streaming_k_way_merge_into`; algorithms verbatim);
   multi-pass chunk merges sink into an open `ArrowWriter`
   (`append_batch_streaming`, 007's plumbing); the final merge runs on
   a `spawn_blocking` thread feeding a bounded (cap 4) channel that IS
   the operator's output stream, and owns spill-dir cleanup on finish,
   error, or receiver-drop.
3. **`fetch`/LIMIT** applied per arriving batch via the SAME
   `truncate_batches_to_limit`; reaching the limit ends the stream and
   aborts the merge thread early.
4. **Merge perf** (to fit the 900s timeout at 250M rows): sort-key
   columns hoisted to once per LOADED buffer (was 2 `evaluate_expr`
   per row-comparison), and `build_merged_batch` gained an
   `arrow::compute::interleave` fast path (per-row take/concat kept
   verbatim as fallback). Both paths still end in
   `batch_with_actual_types`.

Preserved exactly (regression-tested): `truncate_batches_to_limit`
LIMIT enforcement, multi-pass carried-run bookkeeping (`still_needed`),
`batch_with_actual_types` on `flush_run` and merge outputs (Dictionary),
the buffer-transition flush. Join/agg logic untouched beyond shared
helpers. Documented residual: ~3x threshold peak (`flush_run`'s
concat + sort copies of a run buffer), fanin × 8192-row merge read
buffers, ≤4 channel batches.
