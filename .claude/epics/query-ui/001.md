# Task: Engine debug facts: plans and statement facts in QueryMetrics, MemoryPool high-water mark

## Description

Make the engine produce the per-query facts the log will expose, in the
places that already have them.

1. `src/execution/memory.rs`: add `peak: AtomicUsize` to `MemoryPool`;
   `allocate`, `try_allocate` and `MemoryReservation::resize` update it
   with `fetch_max` on the new `used` value; add `pub fn peak(&self)`.
2. `src/execution/context.rs`: extend `QueryMetrics` with
   `optimized_plan: Option<String>`, `physical_plan: Option<String>`,
   `tables: Vec<String>`, `statement_kind: StatementKind`
   (`Select|Ddl|Dml|Other`), `batches: usize`. Fill them inside `sql()`
   from the optimized `LogicalPlan` (`Display`) and the physical root
   (`display_plan`), capped at 64KB with a `…[truncated]` marker.
   `peak_memory_bytes` becomes `pool.peak()` (documented as pool-wide).
   Add `fn collect_scan_tables(&LogicalPlan) -> Vec<String>` (dedup,
   sorted) walking scan nodes.
3. Keep the CLI output (`Memory: peak=`) working; it now prints a real
   peak.

## Acceptance Criteria
- [ ] `MemoryPool::peak()` unit tests: grows on allocate, survives
      release, tracks resize.
- [ ] `ctx.sql("SELECT ...")` returns metrics with non-empty plans and
      the referenced tables for a TPC-H query (test in context tests).
- [ ] A spilling query at a small `--memory-limit` reports
      `peak_memory_bytes` ≥ 50% of the limit (test using an existing
      spill test shape).
- [ ] `cargo fmt --check`, full suite green through the wrapper.

## Technical Details
