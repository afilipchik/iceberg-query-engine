# Task: Query log ring and JSON endpoints (/queries, /queries/{id}, /stats, /tables) wired from HTTP, Flight and fragments

## Description

New `src/distributed/query_log.rs` with `QueryRecord` (all PRD §2
fields, `Serialize`), `QueryLog` (bounded `VecDeque`, `begin` → id,
`finish(id, outcome)`, `fail(id, err)`, `get`, `list(filter)`,
`stats(uptime, pool, cluster)`), percentiles and 60-minute buckets.
Wire it:

- `NodeState.query_log: QueryLog`, `ServeOptions.query_log_size`
  (default 1000, floor 10), `--query-log-size` / `QE_QUERY_LOG_SIZE`
  in `main.rs`.
- `execute_statement(state, statement, mode, origin: QueryOrigin)` where
  `QueryOrigin { front_door, client_addr }`; begin before spawn, finish
  or fail after; the HTTP handler records `result_bytes` and format
  after encoding and sets `x-qe-query-id`. Flight passes its peer addr
  and adds `query_id` to the trailer metadata.
- `/fragment` records `kind: fragment` with the initiator address.
- Routes: `GET /queries` (limit/state/q), `GET /queries/{id}`,
  `GET /stats`, `GET /tables` (name, columns [name,type,nullable]);
  all answer before readiness; `index()` lists them.
