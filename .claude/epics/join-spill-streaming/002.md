# Task: Stream the join output (phase A per batch, phase B per chunk)

## Description

`execute_spill_path` currently returns `stream::iter(all_results)` after
materializing every matched batch. Restructure into a stream with
per-call state: phase A consumes probe batches, probes resident
partitions and yields matched batches immediately (spilling probe rows
for spilled partitions as now); phase A' (build-side SEMI/ANTI) yields
the resident partitions' final emission once the probe stream ends;
phase B iterates spilled partitions and yields per chunk (INNER,
build-side SEMI/ANTI) or per partition (probe-side SEMI/ANTI bitmap).
Probe spill writers are closed exactly once between A and B; probe files
are per call and removed with the operator (Drop) as today. Trace lines
(START/probe collected/DONE) keep their meaning.

### What shipped (`src/physical/operators/spillable.rs`)
- `BuildDecision::Spill(Arc<SpillState>)`; `SpillState` owns the memoized
  partitions / tables / spilled files / spill dir and removes the
  directory in ITS `Drop` — by whichever holder goes last (the operator
  or an in-flight output stream's producer), so a producer can never
  have the directory removed under it and cleanup still happens exactly
  once. The operator-level `Drop` is gone.
- `execute_spill_path` prints START, merges the probe partitions
  (task 001), and spawns a producer task (`run_spill_join_producer`)
  holding the `Arc` + a cloned `SpillJoinCtx` (keys, join type, schema,
  retention mask, threshold, memory pool, per-call id) that sends
  through a bounded `mpsc(8)` → `ReceiverStream`. Phase A
  (`probe_with_spilling`, free async fn): resident partitions probed and
  their output SENT per probe batch; spilled-partition probe rows
  appended to PER-CALL probe files `probe_<call_id>_<idx>.parquet`;
  ANTI's no-build-rows batches sent as before; `tx.is_closed()` per
  probe batch. Phase A': build-side SEMI/ANTI resident emission after
  the stream ends; writers closed exactly once. Phase B
  (`process_spilled_partitions` → `process_spilled_partition`, now
  synchronous and sink-based, on `spawn_blocking` with `blocking_send`):
  per chunk (INNER, build-side SEMI/ANTI) or per partition (probe-side
  SEMI/ANTI bitmap). Errors travel through the channel; the DONE trace
  (same counters) moves to the end of the stream and carries `call_id`;
  an `ABANDONED` trace is new; hash-check lines are unchanged (shared
  `report_key_checksum`). Each call's probe files are removed by its
  own producer on every exit path.
- Tests: `spill_path_repeat_execution_yields_identical_results` (two
  full executions identical and = naive truth; memoized dir survives
  between them; a drained call's probe files are gone; dir removed on
  drop) and
  `spill_path_abandoned_stream_does_not_disturb_a_repeat_execution`
  (stream dropped after one batch, then a full execution = truth; the
  abandoned call's files cleaned up).

**Target miss, stated plainly:** the 1G target was NOT met by this task
alone for the build_right=0 orientation on the cgroup lever. With the
output no longer materialized, the remaining unbounded piece was phase
B reading each spilled partition's WHOLE build and probe files back into
memory (`read_parquet`: ~150MB + ~75MB per partition here, on top of the
resident set and the chunk table) — exactly what task 003's streaming
read-back removes (003: 838 / 839MB COMPLETED on the same legs). Q9 got
SLOWER end to end on this binary because streaming turned the two joins
into a pipeline whose pace-setter was phase A on one thread — measured
(serve at ~1.7 of 32 cores) and fixed in 003.
