# Task: Fix confirmed O(n²) append_to_parquet spill slowness

## Re-scope note (2026-08-24)

This task was originally "fix the wrong-answer bug." Task 001 closed
without confirming that bug's root cause, so per the epic's own
"no guess-fixes" gate, that fix does NOT proceed — do not attempt it
here. Instead, this task fixes a SEPARATE, independently-confirmed
problem task 001 found along the way: `append_to_parquet` in
`spillable.rs` does a full read-entire-file + rewrite-to-temp +
atomic-rename on every spill append. With all 64 hash partitions
spilling almost immediately and hundreds of build batches (plus the
full probe side) getting progressively appended, this is an O(n²)-ish
disk I/O pattern and a strong, evidenced candidate for why even a
CORRECT run of task 001's repro takes 140+ seconds. See
`.claude/epics/spill-join-correctness/001.md`'s Outcome, "A separate,
real finding along the way" section, for the full evidence.

The wrong-answer bug itself (~4.8% of runs, root cause unknown) is
explicitly OUT of scope for this task. Do not attempt to fix it, do not
let this task's changes accidentally mask or alter it — the regression
test added here validates correctness is unchanged, not that the
wrong-answer bug is gone (it isn't, and this task doesn't touch its
mechanism).

## Description

Replace the O(n²) read-rewrite-rename-per-append pattern in
`append_to_parquet` (`src/physical/operators/spillable.rs`) with an
append-friendly approach — the standard fix for this shape is switching
from "rewrite the whole file every call" to either (a) writing each
spilled batch to its own small file within a partition's spill
directory and merging once at read time, or (b) using a true streaming
Parquet writer that appends row groups without re-reading prior
content. Pick whichever fits this codebase's existing spill-read path
with the least disruption — read `process_spilled_partition` and
whatever reads these files back before choosing, since the fix must
stay compatible with however spilled partitions are currently
consumed.
