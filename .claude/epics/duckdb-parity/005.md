# Task: Lance Q19 — IN-list/OR pushdown rendering

## Description

Q19 on lance at SF=100 runs 5.3s vs 1.2s on parquet because the
OR-of-IN-lists predicate is refused by `expr_to_lance_sql`'s whitelist,
so the scan full-decodes. Extend the renderer to `IN (list)` and OR of
renderable conjuncts. Correctness is guaranteed by the invariant that
FilterExec above the scan re-applies the full predicate — a push can
only drop rows the engine would have kept, so unrenderable OR arms must
still refuse the whole predicate (that rule stays).

## Acceptance Criteria

- [ ] Bound the win first: `QE_LANCE_PUSH=all` Q19 measurement recorded before writing gate logic
- [ ] `expr_to_lance_sql` renders `Expr::InList` (literals matching column family) and OR whose arms are ALL renderable
- [ ] Cost gate: decide from the diagnostic measurement whether Q19's shape passes the existing selectivity gate or needs a new heuristic (e.g. conjunct count / IN-list on low-range int + string equality); document the decision
- [ ] Q19 lance SF=100 ≤ 2.5s; SF=100 lance suite total does not regress (Q01-class collapse from over-pushing must not reappear)
- [ ] Lance feature test suite green; SF=10 lance spot-check cell-exact

## Technical Details

- `src/storage/lance.rs`: `expr_to_lance_sql`, `plan_pushdown`,
  `estimate_selectivity`. Remember Lance defect #2: never emit quoted
  identifiers. `MaterializationStyle::AllLate` is already forced.
- Q19's predicate: OR of three conjunct groups over p_brand,
  p_container IN(...), l_quantity ranges, l_shipmode IN(...),
  l_shipinstruct =. Note: on this generator's data Q19 returns ~0 rows
  (degenerate for parquet RT-filters, but the lance win here is decode
  avoidance, which is real regardless).
