# Task: Dictionary-preserving join gather (re-scoped from 2a fusion)

## Description

RE-SCOPED after attribution (see attribution.md): Q9's aggregate burns
243.8s of CPU because group keys arrive as join-gathered PLAIN string
arrays (`n_name`, 25 distinct values, hashed per row over ~604M rows).
The dictionary fast paths in `AggregationState` need `DictionaryArray`
input, which `create_joined_batch` never produces.

Fix at the source: when a build-side column is a string column and the
build side is small (≤ 4096 rows), `create_joined_batch` emits a
`DictionaryArray<Int32>` whose values are the build column AS-IS and
whose keys are the take indices it already computed — near-zero cost,
no string copying at all. Downstream, `AggregationState` (and the
vectorized group table) must treat dictionary group columns via key
indices (machinery partially exists for scan-side dictionaries).

The original 2a probe→aggregate fusion is DEMOTED to a follow-on: the
fused streaming aggregate already overlaps join and agg; attribution
shows the cost is per-row group-key work, not the batch hop.

## Acceptance Criteria

## Technical Details

- hash_join.rs `create_joined_batch`: build-side gather branches
  (row-store / single-batch take / gather_column). The single-batch case
  is the easy one (take indices → dict keys directly). Row-store case:
  skip dict (row store already materializes) or bypass row store for
  small builds — small builds don't take the row-store path anyway
  (check `row_store_eligible`).
- Schema mismatch: output_schema declares Utf8 but the batch column is
  Dictionary(Int32, Utf8). RecordBatch::try_new validates types — so the
  output schema for the joined batch must be adjusted, or downstream
  schemas relaxed. Investigate: the fused agg consumes (batch, exprs) —
  exprs evaluate by name; evaluate_expr on a Column just returns the
  array. The SCHEMA of intermediate joined batches may not need to match
  the logical Utf8 exactly if all consumers tolerate it — verify against
  HashAggregateExec output building and any FilterExec above joins.
  Scan-side dict coercion already crossed this bridge (Rewrite 1) — reuse
  its conventions.
- Sort/output boundary: final output columns must be plain Utf8 —
  merge_states_to_batches builds output from group values; ensure dict
  group values are materialized to strings at OUTPUT time only.
